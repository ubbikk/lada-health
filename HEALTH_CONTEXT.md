### How to maintain this index

1. Save each new medical document or final handout in `docs/`, including PDFs, scans and photographs. Keep original medical records unchanged. Use a descriptive filename with an ISO date, such as `2026-09-14-dobrobut-allergist-consultation.pdf`; existing filenames can stay as they are.
2. Add one row per document, with its date, a relative link to the file, and a short explanation. Say who issued or prepared it, what visit/test/topic it covers, and whether it is an original medical record, patient notes, a proposed test list or a draft. If the date or issuer is unknown, say so rather than infer it.
3. For results, distinguish the sample date from the report date when they differ. For prescriptions, describe what was prescribed without assuming it was taken. Record key verified findings in the relevant health-history section with a link to the original document; this index is a guide to files, not a substitute for their contents.
4. When revising a handout for the same visit, update its file in `docs/` and its index description together. Do not leave the current copy only in `output/`. Preserve a separately named older version if it has already been used or is relevant to the history, and mark which version supersedes it. Keep clinician-issued originals unchanged and add later records separately.
5. Record additions or significant revisions in the update log. Keep source conversations and evidence archives in `sources/`, and generation scripts/intermediate files outside `docs/`. Existing originals in `sources/attachments/` remain preserved; when bringing them into this index, copy them into `docs/` and retain the archive link for provenance.

Template for a new entry:

```markdown
| YYYY-MM-DD (or date unknown) | [Descriptive title](docs/YYYY-MM-DD-descriptive-name.pdf) | Issuer/preparer; document type; what it covers; relevant sample/report dates, status or superseded version. |
```
